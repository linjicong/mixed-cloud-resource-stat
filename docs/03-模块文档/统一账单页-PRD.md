# 统一账单页 PRD

## 一、项目信息

| 项 | 内容 |
| --- | --- |
| 文档语言 | 中文 |
| 项目名称 | `unified_bill_page`（多云统一账单页） |
| 所属系统 | 多云资源统计系统 mixed-cloud-resource-stat |
| 技术栈 | 后端 Spring Boot 4.0.3 + MyBatis-Plus 3.5.16 + MySQL；前端 Vue 3 + Vite + Element Plus 2.14 + ECharts 6 + Pinia |
| 需求原话 | "我要做一个统一的账单页,可以看到全部账号的费用总览和各个账号的费用情况,账单情况及历史费用图表等" |
| 数据来源约束 | 仅使用本地已采集表：`h_cloud_bills_fee_records`、`h_cloud_bills_monthly_break_down`、`q_cloud_bill_resource_summary`。不新建采集任务、不调用第三方账单 API。阿里云账单暂无数据，页面以"暂无数据"占位，禁止造假数据。 |
| 金额口径 | 以实付金额为主（现金 + 代金券 + 赠送账户 + 信用等实际支付部分），明细中保留原价/优惠后总价便于核对。 |

### 现状调研结论（已确认，直接采信）

- 三张账单表均已落库，且都继承 `BasicEntityExtend`，统一携带 `confName`（账号/配置名）、`confProvider`（厂商标识）、`confRegion`。**这是"统一账单"能够跨账号、跨厂商聚合的基础键**。
- 账号主数据在 `cloud_conf`（`name` 供应商名称、`provider` 供应商标识、`region`、`enable`）。
- 后端已有 `ResourceController` 暴露 `GET /huawei/bills`（月度账单明细）、`GET /huawei/bills_fee_records`（费用记录）、`GET /tencent/bills`（账单资源摘要），均支持 `confName` 过滤，但**返回全量列表、无聚合、无分页、无账期筛选**，前端无法直接用于账单页。
- 前端 `Summary.vue`（跨云汇总）目前只统计**资源数量**（EC2/CVM/ECS 个数），没有任何金额维度。
- 前端 `App.vue` 侧栏已有各厂商"账单统计"入口，但**没有跨厂商统一入口**；`router/index.js` 中不存在 `/bills` 路由，需新增。
- 现有 `frontend/src/apis/cloud.js` 无任何账单聚合 API 方法，需新增。

### 本 PRD 的边界（不做什么）

- 不做账单数据采集、不做同步任务改造、不做账单修正/调账写入。
- 不做预算告警的实时推送（列 P1/P2）。
- 不做账户权限隔离（系统当前无登录体系）。

### 5.2 华为云实付金额

推荐主口径（**基于费用记录表 `h_cloud_bills_fee_records`**）：

```
华为云实付(主) = cash_amount + coupon_amount + credit_amount
```

理由：

1. `fee_records` 是华为云"按交易/按账期结算"的费用记录，字段粒度与"这个月实际付出去多少钱"直接对应，`cash_amount`（现金）、`coupon_amount`（优惠券）、`credit_amount`（信用/欠费抵扣）构成真实支付来源，语义与腾讯云的 Cash/Voucher/Incentive 高度同构，是最容易做跨云对齐的口径。
2. `consume_amount`（消费金额）在华为云口径中是"应付金额"，不是"已支付金额"，通常会包含尚未实付的欠费（`debt_amount`），直接求和会高估现金流出。
3. `official_amount` 与 `consume_amount` 之间的差额体现折扣，页面同时保留这两个字段即可让用户核对"打折打了多少"，无需把折扣塞进实付。

可选补充口径（**基于月度账单明细 `h_cloud_bills_monthly_break_down`**）：

```
华为云实付(摊销) = amortized_cash_amount + amortized_coupon_amount + amortized_credit_amount
```

差异与风险（必须写进页面口径说明，也必须在 PRD 中留痕）：

| 风险 | 说明 | 处理建议 |
| --- | --- | --- |
| 口径混用导致总额对不上 | 费用记录是"现金流视角"（这个月付了多少钱），摊销是"成本归属视角"（这笔钱该摊到哪几个月）。**两者数值必然不等**，包年包月场景差异尤其大。 | 全页只允许一个口径参与聚合，**默认用费用记录口径**；摊销口径仅作为 P2 可选切换，绝不可在同一张图里混算。 |
| 两表账期覆盖不重叠 | 若某账号只采集了其中一张表，会导致该账号在某些账期"消失"。 | 聚合时对每个 (账号, 账期) 按"有数据的那张表"取值，并在响应中标记 `amountSource`（fee_records / break_down / mixed），供明细表角标展示。 |
| 字段可能为 null | 三张表的金额字段均可能为 null。 | 求和一律走 COALESCE(field, 0)，禁止 null 传播导致整行丢失。 |
| 欠费与抹零 | `debt_amount`、`erase_amount`、`writeoff_amount` 是否计入实付存在争议。 | **默认不计入实付**（它们不构成当期实际支付），但在明细表单独列展示，供财务判断。 |
| 退款/负金额 | 交易类型中存在退款，金额可能为负。 | 保留负值参与求和（否则总额虚高），明细表用红色 + 负号展示。 |

### 5.3 腾讯云实付金额

```
腾讯云实付 = toNumber(CashPayAmount) + toNumber(VoucherPayAmount) + toNumber(IncentivePayAmount)
```

理由：三者分别是现金账户、代金券、赠送账户的实际扣减，天然即"实付"。`RealTotalCost`（优惠后总价）作为"应付"参考值展示，`TotalCost`（原价）作为原价展示。

校验规则（建议在实现中做，作为数据质量兜底）：
`abs(RealTotalCost - (实付 + 未支付部分)) ` 应在一个小容差内；若差异显著，在明细表该行标注"数据异常"角标，而不是静默修正金额。

注意：腾讯云这三张金额字段在实体中是 **String** 类型（见 `QCloudBillResourceSummary`），必须做安全数值转换（空串、`"-"`、千分位逗号均需处理），转换失败按 0 处理并计入异常计数。

### 5.4 计费模式统一

华为云 `charging_mode` 为 Integer 编码，腾讯云 `PayModeName` 为已翻译文本。需建立统一枚举（建议值：包年包月 / 按需 / 预留实例 / 资源包 / 节省计划 / 其他），后端在归一化层完成映射，前端只消费统一文本，避免前端写厂商分支。

### 5.5 环比与同比

```
环比 = (本期实付 - 上期实付) / 上期实付 × 100%
同比 = (本期实付 - 去年同月实付) / 去年同月实付 × 100%
```

- 上期/去年同月为 0 或负数时，不展示百分比，展示"不可比"。
- 若筛选为区间（如 3 个月），环比对比"紧邻的等长前置区间"。
- 同比在数据不足 12 个月时，接口返回 `yoyAvailable=false`，前端置灰并提示"数据不足 12 个月"。

| 账期范围 | 月份区间选择器（el-date-picker type="monthrange"） | 当前月往前 2 个月 ~ 当前月（即近 3 个月） | 变更后所有区块重算；最大可选范围限制 24 个月，超出提示 |
| 厂商 | 多选下拉 | 全部（华为云、腾讯云、阿里云） | 变更后账号下拉的候选集只保留所选厂商的账号；若已选账号不属于新厂商则自动移除 |
| 账号 | 多选下拉（可搜索，显示"账号名（厂商）"） | 全部 | 变更后全页联动；提供"全选/清空" |
| 重置 | 文本按钮 | — | 恢复全部默认值 |

数据来源：厂商与账号列表复用已有 `GET /cloud-configs`，按 `provider` 分组、只取 `enable=1` 的配置，避免把停用账号混进账单视图（停用账号的历史账单仍应在"全部"下可查 → 实现需注意：**账号下拉默认只列启用账号，但已选中的停用账号仍可保留**）。

### 6.3 KPI 卡片区

| 卡片 | 主值 | 副值 | 空态 |
| --- | --- | --- | --- |
| 区间实付总费用 | 区间内所有账号实付求和（元，千分位分隔，保留 2 位） | 环比百分比 + 涨跌箭头（涨红跌绿，符合成本直觉） | 显示 `--`，副值"暂无数据" |
| 本期账号数 | 总数 / 产生费用账号数 | 悬停展示"有 N 个账号区间内无账单" | 显示 `0 / 0` |
| TOP 产品 | 产品名（超出省略号 + tooltip） | 该产品金额 + 占比 | "暂无产品数据" |
| 原价 / 优惠 | 原价合计 | 优惠合计 + 折扣率（优惠/原价） | 若该厂商无原价字段（如华为云无账单表覆盖），仅展示可算部分并标注 |

### 6.4 历史趋势图（左侧）

- 图表：ECharts 组合图，X 轴月份，左 Y 轴金额。堆叠柱按厂商（华为云/腾讯云/阿里云），折线为合计实付。
- 切换：近 6 月 / 近 12 月按钮组，切换只改接口时间窗参数，其他筛选条件保持。
- 交互：tooltip 显示 `月份 / 合计 / 各厂商金额 / 环比`；点击某月柱子 → 将顶部账期范围收窄为该单月（下钻）；图例可点击隐藏某厂商。
- 空态：所选范围内无任何数据 → 展示"所选范围内暂无账单数据"占位图（不画空坐标系）。
- 加载态：图表区域骨架屏 + 顶部细进度条。

### 6.5 费用占比图（右侧）

- 图表：环形图。切换维度：按厂商 / 按账号（账号超过 8 个时，第 8 名之后合并为"其他"，并保留 tooltip 明细）。
- 交互：hover 高亮对应扇区 + 显示金额与占比；点击扇区 → 账号维度时联动账号明细表高亮并滚动到该行；厂商维度时联动筛选区厂商条件。
- 空态：同 6.4。

### 6.6 账号费用明细表

列定义：

| 列 | 说明 |
| --- | --- |
| 账号名 | `conf_name`，同时展示厂商 tag（华为云/腾讯云/阿里云，不同颜色） |
| 厂商 | `conf_provider` 映射文本 |
| 区间实付 | 该账号在筛选区间内实付合计 |
| 占比 | 该账号实付 / 所有账号实付合计，保留 1 位小数 |
| 环比 | 与等长前置区间对比，无数据显示"不可比" |
| 近 6 月趋势 | 内联迷你折线图（sparkline），取该账号近 6 个月实付；无数据时显示 `—` |

交互：
- 默认按区间实付降序；支持点击表头按实付/占比/环比排序。
- 点击行 → 下方账单明细表自动把"账号"筛选设为本行账号并滚动到明细区。
- 阿里云账号：若存在 cloud_conf 但无账单数据，仍展示该行，实付显示 `--`，占比 0%，并加"暂无账单数据"角标，**不参与占比分母**。

### 6.7 账单明细表

- 筛选：账期（单月/区间）、账号、厂商、产品大类、计费模式；与顶部筛选区**双向同步**（顶部账号筛选变化时，明细表账号条件同步；明细表内单独改账号不影响顶部全局筛选，以避免误操作，需在 UI 上以"明细内筛选"标签区分）。
- 列：账期、账号、厂商、产品大类、子产品/资源类型、计费模式、原价、优惠金额、实付、地域、资源 ID/名称、数据来源角标（费用记录/月度明细）。
- 排序：实付、原价、账期、交易时间，服务端排序。
- 分页：默认 20 条/页，可选 20/50/100；服务端分页。
- 空态：区分两种——"无符合条件的账单"（有数据但筛掉了）与"该厂商账单数据暂未采集"（阿里云）。
- 行展开（建议）：展开行显示该笔账单的细分字段（现金/代金券/信用/赠送账户/欠费/抹零），满足"保留明细便于核对"的要求。

### 6.8 产品费用 TOP

- 横向条形图：TOP N 产品（按实付降序），条上标注金额与占比。
- 表格：产品名、厂商、实付金额、占比、涉及账号数、涉及资源数（若可算）。
- 切换：TOP 5/10/20；按厂商 / 按账号过滤维度（与顶部筛选叠加）。
- 交互：点击某产品 → 账单明细表自动按该产品筛选。
- 空态与加载态同其他区块。

### 6.9 全局状态与降级策略

| 场景 | 表现 |
| --- | --- |
| 首次加载 | 各区块独立骨架屏，KPI 先返回（轻量聚合），图表后返回 |

## 七、待确认问题（含默认假设，不阻塞开发）

| 编号 | 问题 | 默认假设（按此实现，用户可后续推翻） |
| --- | --- | --- |
| Q1 | 华为云实付用"费用记录（现金流）"还是"月度明细（摊销成本）"口径？包年包月场景下两者差异可能很大。 | 默认用 **费用记录 = cash + coupon + credit**；摊销口径作为后续可切换项，本期不做切换 UI，不做混算。 |
| Q2 | 欠费 `debt_amount`、抹零 `erase_amount`、核销 `writeoff_amount` 是否计入实付？ | 默认**不计入实付**，仅在明细展开行中展示，供财务自行判断。 |
| Q3 | 阿里云账单后续由谁补采集？页面上是否需要预留"阿里云账单"独立 tab？ | 本期不做 tab，只在页面底部留说明条 + 账号表中占位行；采集能力由后续需求立项。 |
| Q4 | 默认账期范围用"近 3 个月"还是"上一个完整账期"？月初时当月数据往往不完整。 | 默认 **近 3 个月（含当月）**，但 KPI 主卡的"环比"以"最近一个完整账期"为准，避免当月未出账导致环比失真；页面标注"当月为进行中账期"。 |
| Q5 | 账号停用后是否仍计入历史账单统计？ | 默认**计入**（历史费用是既成事实），但账号下拉默认只列启用账号；停用账号在明细表中加"已停用"tag。 |
| Q6 | 是否需要区分"应付"与"实付"两套金额指标？ | 默认主指标只做成实付，原价/优惠作为辅助列；若后续财务需要"应付口径"，再增加指标切换。 |

## 八、验收清单（交给测试的快速核对项）

1. 全部账号合计 = 各账号实付之和（允许 ≤0.01 元浮点误差）。
2. 占比之和 = 100%（四舍五入后允许 ±0.2%）。
3. 切换账期/厂商/账号后，KPI、趋势、占比、两张表、TOP 同步变化，无残留旧数据。
4. 上期为 0 时环比显示"不可比"而非 Infinity/NaN。
5. 阿里云在无数据时显示占位说明且不影响任何合计。
6. 明细表分页 total 与筛选条件一致；排序为服务端排序且稳定。
7. 三张表中金额字段为 null/空串/`"-"` 时不出 NaN，按 0 参与计算并计入异常计数。
8. 图表空态不渲染空坐标系；加载态不出现布局抖动。
9. 华为云与腾讯云账单在同一张趋势图中可正确堆叠，账期格式统一为 `YYYY-MM`。
10. 明细行展开可看到实付的构成拆分（现金/代金券/信用/赠送账户）。
